## Pourquoi aucune trame data: dans les deux cas — défaut PRÉEXISTANT, hors périmètre du refactor
Le consommateur MatchingNotificationConsumer est servi par la fabrique Kafka par défaut (value-deserializer ByteArrayDeserializer,
application.yml l.54) sans convertisseur JSON : chaque message échoue avant d'atteindre le flux. Journal du conteneur, sur les deux binaires :
  246d2ce 03:45:16 ERROR DefaultErrorHandler ... Cannot convert from [[B] to [...MatchingNotificationEvent] ... gofp.matching.notifications-0@0
  e25403e 03:59:09 ERROR DefaultErrorHandler ... Cannot convert from [[B] to [...MatchingNotificationEvent] — même erreur (MessageConversionException), compte dans le journal : 1
Le publieur applicatif (KafkaEventPublisher.publishMatchingNotification) passe en plus par l'outbox avec une enveloppe DomainEventEnvelope,
dont la forme n'est pas celle de MatchingNotificationEvent. Aujourd'hui, en local comme (vraisemblablement) en prod, le mobile ne reçoit
donc que le commentaire ':connected'. Le contrat des trames data: est prouvé par NotificationStreamControllerSseContractTest, pas par le run.
