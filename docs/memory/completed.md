# Details

## 2026-07-08 — Kernel-facade migration: all 10 mandated modules complete (ADR-008–016)
Ran the mandated "Core as Kernel facade/BFF" migration process (`docs/kernel-api/endpoints.md`+`schemas.md` vs. current module logic) across all 10 modules in the prescribed order: `tnt-media-core` → `tnt-resource-core` → `tnt-product-core` → `tnt-inventory-core` → `tnt-sales-core` → `tnt-accounting-core` → `tnt-actor-core` → `tnt-organization-core` → `tnt-tp-core` → `tnt-administration-core`. Full detail in `architecture/decisions.md` ADR-008 through ADR-016; summary:

- **The headline bug (ADR-012)**: verified live against `kernel-core.yowyob.com` that every Kernel response is wrapped `{success, data, message, errorCode, timestamp}`. Every `Kernel*Adapter` except `tnt-auth-core`'s deserialized the raw body directly into a flat DTO, skipping the envelope — combined with universal fail-open error handling, this meant these "existence check" adapters have *never* been able to read real data back, even on a successful 200 response (Jackson silently produced an all-null/default object). Fixed with a new shared `KernelEnvelope`/`KernelResponses` helper (`foundation/tnt-common-core`, `com.yowyob.tiibntick.common.kernel`) applied to 9 adapters across `tnt-resource-core`, `tnt-product-core`, `tnt-organization-core`, `tnt-tp-core`, `tnt-administration-core`, `tnt-roles-core`, `tnt-notify-core`, `tnt-sales-core`, `tnt-accounting-core`.
- **Also found and fixed**: missing `/api` prefix on 3 adapters (`KernelActorAdapter`, `KernelProductAdapter`, `KernelOrganizationAdapter` — the last had a stray `/v1/`); a dead method calling a nonexistent Kernel resource in `tnt-inventory-core` (deleted); DTO field-name mismatches (`id` vs `kernelXxxId`, an `isActive` boolean the Kernel doesn't model) fixed in `KernelSalesOrderDto`/`KernelInvoiceDto` where the real schema was already in hand.
- **`tnt-actor-core`** (zero Kernel integration going in) got a brand-new `IKernelActorPort`/`KernelActorAdapter`/`KernelActorDto`, wired fail-open into all 4 profile-creation services (Client/Freelancer/Deliverer/RelayOperator) — the mission's one genuine "build from scratch" deliverable. 3 new tests, all 42 module tests pass.
- **Real duplication found but deliberately NOT executed** (flagged as follow-ups, not silently dropped): `tnt-product-core`'s catalog fields plausibly duplicate the Kernel's `product-structure-controller` (ADR-010); `tnt-accounting-core`'s `Account`/`JournalEntry` persistence plausibly duplicates the Kernel's much more complete accounting/reporting engine (ADR-013). Both need a dedicated data-migration-aware session — not something to guess through in one pass, given production-data and (for accounting) financial-audit stakes.
- **Confirmed correctly local, no Kernel equivalent worth adopting**: `tnt-media-core` (MinIO storage, WORM legal retention, QR/PDF/signature rendering — ADR-008), `tnt-resource-core` (fleet/vehicle management vs. Kernel's generic IoT-shaped resource registry — ADR-009), `tnt-organization-core`/`tnt-tp-core` (their hard-blocking existence-check design was already correct — ADR-015), `tnt-administration-core`'s `TntRoleTemplateRegistry` (it's the source *pushed to* the Kernel, not sourced from it — ADR-016).
- Found one pre-existing, unrelated test/implementation drift in `tnt-tp-core` (`TntClientProfileServiceTest` expects `IllegalArgumentException`, service throws `ResponseStatusException`) — flagged in known-issues.md #14, not fixed (out of scope).

## 2026-07-08 — `tnt-auth-core` Kernel auth/SSO gateway (Bloc A, later Bloc B+C) — since superseded by ADR-017
Built `tnt-auth-core` proxies for the Kernel's `auth-controller` (24 ops) + `auth-oidc-controller` (6 ops), so platform backends (Agency/Go/Link/Market) stop calling the Kernel directly for auth. Extended the same day to Bloc B (SSO context-resolve/token-exchange) and Bloc C (agency onboarding orchestration, `identity/tnt-administration-core`), plus a config-driven (`.env`-based) platform-client registry. **This entire mechanism was rebuilt as a dedicated module the very next day** — see the 2026-07-09 entry below and `architecture/decisions.md` ADR-017 — kept here for history since the design doc (`docs/auth/platform-client-management-design.md`) documents both rounds.

## 2026-07-09 — `tnt-platform-gateway-core`: DB-backed platform Client-ID/API-Key system
New foundation module replacing the `.env`-based registry above with a persistent, admin-managed system: BCrypt-hashed API keys (show-once plaintext), key rotation with grace window, immediate revocation, a two-level `resource:action` scope model enforced by a new `PermissionMatcher` (shared with human-user RBAC), and full audit logging. Admin CRUD gated to `TNT_ADMIN` only. Same-day follow-up round changed the API key format to `tnt_<base64(32 random bytes)>`, deleted the `.env` fallback entirely (confirmed unused), and made new clients get `*` scope automatically at creation. See `architecture/decisions.md` ADR-017, `security/platform-gateway-credentials.md`, `docs/auth/platform-client-management-design.md`.

## 2026-07-24–25 — Platform-client production rollout + R2DBC `Persistable` bug
Issued 5 platform-client identities (Agency, Link, Go, Market, App Mobile) with API keys on the real deployed instance `tiibntick-core.yowyob.com`. Root-caused and fixed a bug that had silently blocked **all** platform-client/API-key creation since the module's 2026-07-09 launch: the affected R2DBC entities assigned their own client-side `@Id`, so Spring Data R2DBC issued a no-op `UPDATE` instead of an `INSERT` on every "create" call, with no error thrown. Fixed via `Persistable<String>` + a shared `TntPersistableEntity` marker (commit `efdecebb`). See `architecture/decisions.md` ADR-020 and `knowledge/known-issues.md` #18.

## 2026-07-25 — Tracking codes + GPS-to-Kalman ETA pipeline made real end-to-end
Two related "designed but never actually connected" gaps closed: `Delivery.create()` never assigned a tracking code despite the VO/column/index/query all already existing (`GET /track/{code}` always 404'd); and `tnt-realtime-core`'s ETA computation was a hardcoded stub ("30 min, 90% confidence" regardless of input) with zero real callers of `tnt-route-core`'s Kalman-filter use case. Both fixed end-to-end (tracking code threaded through delivery→incident→dispute; real GPS→Kalman wiring via constructor injection). A parallel, structurally-broken Kafka-based ETA path was deleted rather than patched. See `knowledge/known-issues.md` #21/#22.

## 2026-07-10 → 2026-07-31 — `tnt-go-freelancer-point-back-core` (L6-Bis): from BFF re-import to a real announcement/matching pipeline
This module has its own 20-commit history, reviewed in full 2026-07-31. Timeline: finalized and wired into `TntCoreConfig` 2026-07-10; caught by the same-week botched-merge repair (`fcd7bf9e`) and the Chantier A authentication-on-mutations fix (`f23204b2`, 2026-07-18); its `KafkaGofpEventPublisher` migrated to the transactional outbox with a real Testcontainers integration test 2026-07-22; a large `486f4872` "resync with the core architecture" commit 2026-07-23 pulled in ~30 Liquibase migrations from the original standalone BFF codebase and, as a side effect, deleted that one integration test without replacement; a real BERT-based (DJL/PyTorch) sentiment-analysis model replaced a keyword scorer for evaluations 2026-07-27; the R2DBC `Persistable` bug (see #18) was independently re-applied here 2026-07-29 (this module's entities have the same client-assigned-id pattern); and 2026-07-29–31 saw a burst of fixes (schema alignment, HTTP error mapping, delivery-needs/assistance/SSE/registration gaps) culminating in a full rewrite of `AnnouncementApplicationService`/`MatchingUseCase` to delegate the announcement lifecycle to `tnt-delivery-core` instead of maintaining a competing local one. See `architecture/decisions.md` ADR-021 for the resulting design (the `FIXED_PRICE`/`QUOTE_REQUEST` dual pricing mode that implements TiiBnTick's two product experiences — "Go," where the client sets the price upfront, and "Freelancer," where freelancers bid — on one shared matching/escrow pipeline) and `knowledge/known-issues.md` #23–25 for what's still rough (zero test coverage, a late price-validation gap, and a mixed port/security convention left over from the module's BFF origins).

## 2026-07-31 — `tnt-go-freelancer-point-back-core`: 4 architecture/consistency findings fixed same-day
Following the 2026-07-31 review above, the user asked for all 4 weaknesses to be fixed immediately:
1. **Delivery-core coupling removed**: `MatchingUseCase`/`AnnouncementApplicationService` no longer import any `tnt-delivery-core` type. New `IDeliveryAnnouncementPort` (owned by gofp) + `AnnouncementSnapshot`/`AnnouncementResponseSnapshot`/`PublishAnnouncementPortCommand`/`RespondToAnnouncementPortCommand` records, implemented by `DeliveryAnnouncementPortAdapter` — the sole class left touching `DeliveryAnnouncement` directly. `resolveEscrowAmount` stays a delegated port call so the FIXED_PRICE/QUOTE_REQUEST rule isn't duplicated.
2. **Port convention unified**: all ~59 files under `domain/port/{in,out}` moved into `application/port/{in,out}` (module-wide `sed` on the import paths, verified by full compile). 3 dead duplicate interfaces (`IAnnouncementUseCase`, `IDeliveryNeedUseCase`, `IOpeningHoursUseCase` — confirmed zero real callers) deleted rather than merged.
3. **Security model unified**: the 4 admin controllers (`AdminController`, `AdminClientController`, `AdminFreelancerController`, `AdminRelayPointController`) switched from `@PreAuthorize("hasAnyRole('ADMIN', 'TNT_ADMIN')")` (checking a role, `ADMIN`, that doesn't exist among this repo's 10 canonical `TntRole`s) to `@RequirePermission(resource = "gofp-admin", action = ...)`, matching the app-wide convention.
4. **Test coverage added** (previously zero): `GofpEventPublisherPortAdapterOutboxIntegrationTest` (Testcontainers Postgres + embedded Kafka, recreating the coverage lost 2026-07-23), `AnnouncementApplicationServiceTest` (5 tests, both escrow branches + the no-double-charge invariant + freelancer-quota rejection), `DeliveryAnnouncementPortAdapterTest` (4 tests, pricing-mode mapping + the address fallback-landmark safety net). All 9 unit tests + the 1 integration test pass; a pre-existing, unrelated `tnt-roles-core` test failure (asserting an outdated 9-role list against the now-10-role `TntRole` enum, from the same-day `AGENCY_HUB_OPERATOR` commit) was confirmed via `git log` to predate this work and was left alone.

A closer read of `DeliveryAnnouncement.addResponse()` while building the adapter also surfaced that one of the 4 original findings' supporting detail was itself wrong — `QUOTE_REQUEST` pricing *was* already validated at respond time (`validateResponsePricing`), not only at selection as first claimed. Corrected in `knowledge/known-issues.md` #24 rather than left standing. See `architecture/decisions.md` ADR-021 for full detail.
